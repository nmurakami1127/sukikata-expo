> 先行実装済みのロボット掃除機関連タスク21件（`taskData.ts` の `floor_robot_001`〜`floor_robot_021`）を
> A/B/Cの3区分に仕分けた一覧である。企画から区分・重み付けルール・記録分離方針の承認回答（2026-09-16）を

## 区分の定義

- **A：通常タスクとして残す** — ロボット掃除機の有無に関係なく日常的に意味がある。改訂版5-3の例示に該当・近似するもの。ロボット掃除機所有者向けの重み付け対象からは外し、既存の一般床タスクと同列に扱う想定。
- **B：所有者では優先度（weight）を下げる** — 内容自体は既存の「床」タスクとして存置可能だが、改訂版5-2が指す「細かい単位で何度も片付ける」「実際の一括片付け行動と合わない、過度に細分化された」タスクに該当。ロボット掃除機所有者（`robotVacuumStatus === "owner"`）に対してのみ重みを下げる対象。
- **C：購入検討者向け「迎える前チェック」に転用可能** — 改訂版8章の独立フローに移設する候補。通常の床タスクプールからは外れる想定。

「ロボット掃除機所有者だから優先表示する専用タスク」という第4の区分（初版6-2）は、改訂版要求により設けない。

**反映内容（確定・データ基盤のみ実装済み）**：`taskData.ts`の`TASKS.floor`配列から削除し、独立した`export const ROBOT_CHECK_TASKS: Task[]`として切り出した。通常の「床」カテゴリ選択ロジック（`pickTaskForCategory`）からは一切参照されない。「表示・完了」の記録は`taskStats`を共用せず、専用の記録先を新設する方針で確定（`robot_check_started`/`robot_check_item_checked`/`robot_check_completed`の3イベントで計測）。ただし「迎える前チェック」の画面・状態遷移・専用ストレージの実装自体は今回のスコープでは未着手（詳細は実装指示書3章）。

## 解消済みの論点（2026-09-16、企画回答により確定）

1. **B区分の「重みを下げる」度合い**：新規独立定数`ROBOT_OWNER_DEMOTION_MULTIPLIER = 0.5`（暫定値）を新設して確定。既存`ROBOT_AUDIENCE_WEIGHT_MULTIPLIER`の逆数は流用しない。
2. **B区分タスクの購入検討者（`considering`）向けの扱い**：「通常の重み（調整しない）」で確定。現状維持。
3. **A区分タスクの`tags`・`audiences`の要否**：`tags`は残す（分析・コンテンツ分類目的）、`audiences`は削除する（選択ロジック側では通常タスク扱いにする）で確定。

## 残る論点（実装指示書3章参照）

- `robot_check_item_checked`の発火粒度
- 「迎える前チェック」への導線をホーム画面のどこに配置するか
