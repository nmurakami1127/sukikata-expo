# スキマかたづけ（愛称：スキかた）MVP開発指示書

## 0. 目的
「5分×小分けタスクの積み重ねで、片付け行動が継続するか」という仮説を、最小コストで検証する。AI・アカウント基盤・課金導線など複雑な要素は今回のスコープに含めない。

## 1. プロダクト概要

| 項目 | 内容 |
|---|---|
| アプリ名 | スキマかたづけ（愛称：スキかた） |
| コンセプト | 「片付けよう」を「片付いた」に変える、空き時間の5分から始めるアプリ |
| 3本柱 | ①始めるハードルを下げる ②続ける理由をつくる ③完璧を求めない |
| 対象 | 片付けが苦手な人全般。特に選択疲れ・完璧主義で挫折しやすい人 |
| プラットフォーム | iOS / Android（React Native または Flutter、1ソースで両対応） |
| 想定開発期間 | 6〜8週間 |
| 想定体制 | PM1名、デザイナー1名、エンジニア1〜2名 |

## 2. MVPスコープ（Must機能）

### 2-1. 場所選択 → タスク提示
- ユーザーが場所カテゴリ（机／床／棚・収納／キッチン／リビング／玄関／クローゼット／デジタル・カバン類の8カテゴリ）を選択
- 選択したカテゴリ内のタスクリストから1件をランダム表示（詳細は「4. タスクデータ仕様」参照）
- 「このタスクはやらない／別のタスクを見る」でスキップ可能。スキップは記録するが表示継続は妨げない
- 完了したタスクは直近14日間は再出現させない（別紙タスクプール40件超を確保することで枯渇を防止）
- **AI・画像解析は実装しない。** 完全にルールベースのランダム/ローテーション表示でよい

### 2-2. 5分タイマー
- タスク開始時にシンプルなカウントダウンタイマーを起動（デフォルト5分、変更不可でよい）
- タイマー終了時に音・バイブで通知。継続/終了はユーザーの任意（「まだやる」「ここで終わる」の2択を出す）
- タイマー中でも「完了した」ボタンでいつでも終了できる

### 2-3. Before/After写真
- タスク開始前・終了後にそれぞれカメラ起動→撮影（任意、スキップ可）
- 加工・比較UI（フィルタ、スライダー比較等）は実装しない。撮って保存するだけ
- 写真はローカル端末に保存。クラウド同期は不要（MVPでは不要、後続フェーズで検討）
- 「写真を撮るだけで完了扱い」を選べるようにする（何もタスクをこなせなくても記録だけで達成扱いにする救済導線）

### 2-4. ストリーク表示
- 連続実施日数をホーム画面にカウンタ表示
- **「お休みチケット制」を採用**（詳細仕様は6-3）。1日サボったら即0に戻る厳格な仕様にはしない
- 「今週の実施日数」（例：今週3/7日）を併記し、連続日数だけに依存しない表示にする

### 2-5. プッシュ通知
- 1日1回、固定時刻（初期設定はユーザーが設定、デフォルト19:00等）にリマインド
- 義務調・焦らせる文言は一切使わない（確定文言は6-4を参照）
- 1日に送るプッシュ通知は最大1件。設定画面でオン/オフ・時刻変更を必ず用意する

## 3. MVPに含めない機能（Nice to have）
- AI画像解析によるタスク自動提案
- モノの「住所」管理機能（収納場所の記録・検索）
- 家族・同居人との共有機能
- プレミアム課金・広告導線
- クラウド同期・アカウント登録
- SNSシェア機能

これらは β 版のデータを見てから優先順位を再検討する。

## 4. タスクデータ仕様

### 4-1. データ構造（例：JSON）
```json
{
  "id": "desk_001",
  "category": "desk",
  "title": "机の上のゴミだけを捨てる",
  "note": "分別は考えず、明らかなゴミのみ",
  "cooldown_days": 14
}
```

### 4-2. カテゴリ一覧
机／床／棚・収納／キッチン／リビング／玄関／クローゼット・衣類／デジタル・カバン類（計8カテゴリ、各4〜5タスク、初期タスクプール約35件）

### 4-3. タスク作成の3ルール（コンテンツ担当・エンジニア共有事項）
1. 「全部」「毎日」を使わない。常に数量（1つ・3つ）か範囲（一段・1畳）で区切る
2. 判断が必要な作業（捨てる可否の判断など）は最小限にする。「集める」「戻す」「拭く」など判断負荷の低い動詞を優先
3. 「写真を撮るだけで完了」にできる選択肢を必ず残す

タスク文言の全リストは別紙「タスクリスト一覧」を参照。

## 5. デザイン仕様

### 5-1. カラーパレット
| 用途 | 名称 | Hex |
|---|---|---|
| 背景 | 生成りベージュ | #F5F1E6 |
| メインアクセント | セージグリーン | #8FA888 |
| サブアクセント（達成の瞬間のみ使用） | ダスティコーラル | #E7A08E |
| サブアクセント | マスタード | #D9AE63 |
| テキスト | 墨インク | #3E3A34 |

### 5-2. タイポグラフィ・アイコン
- 書体：丸ゴシック系（角の立たない、柔らかい印象のフォント）
- アイコン：1〜2色のフラットデザイン。ホーム画面で浮かない主張度
- シグネチャーモチーフ：「すきまに芽吹く」＝2つのブロックの隙間から芽が伸びるマーク
- 掃除道具（ほうき等）のモチーフは使用しない
- **最終アセット済み**：マスターSVG（1024×1024、単体アイコン、フルブリード・角丸なし）から、iOS（1024/180/167/120px）・Android（512/192/144/96/72/48px）の主要サイズPNGを書き出し済み。OS側の自動マスキングを前提に、素材は正方形フルブリードで統一
- 未対応：Androidアダプティブアイコン用の前景/背景分離レイヤー、スプラッシュ画面用の単色ロゴ（ライト/ダーク）は別途書き出しが必要

### 5-3. NGトーン
- ビビッド・原色は「やる気の強要」に見えるため使わない
- 劇的すぎるBefore/After訴求（圧の強いビジュアル）は避ける
- 「もっと頑張れそう」という誘導コピーは一切使わない

## 6. コピー（実装用テキスト）

### 6-1. オンボーディング（5画面）
1. 共感：「片付けなきゃ」が、いちばん疲れる。大丈夫、今日は何もしなくていい。
2. 課題提示：片付けられないのは、意志が弱いからじゃない。「どこから」がわからないだけ。
3. 解決策：だから「スキかた」は、5分だけ。場所を選べば、やることは決まってる。
4. 体験予告：タイマーが鳴ったら、そこで終わり。やり残しがあっても、それでいい。
5. CTA：まずは、今いる場所から。［ 5分だけ、はじめる ］

### 6-2. ストア掲載文（ASO）
- アプリ名：スキマかたづけ - すきま時間の片付け習慣
- サブタイトル：空き時間に、5分だけ。写真で見える化する片付け習慣
- プロモーションテキスト：ちょっとの空き時間も、CM中も。「スキかた」で、ふとした瞬間がちょっとの前進に変わる。
- 説明文・キーワードは別紙ASO資料を参照

### 6-3. ストリークの「お休み」猶予ルール
- 毎週日曜0:00に「お休みチケット」を**2枚**付与（繰越なし、ストック上限2枚）
- 未実施日はチケットを1枚自動消費して連続日数を維持。チケット0の状態で未実施だとリセット
- リセットされても「過去の最長記録」は保持し、常に表示し続ける
- タスク完了・Before/After写真の撮影のみ、どちらでも「実施日」としてカウントする
- UI：連続日数＋チケット残数（アイコン2つ、消費でグレーアウト）。リセット時は数字だけでなく前向きな一文を添える

### 6-4. 通知文言
**通知許可のリクエスト画面**
```
毎日同じ時間に、そっと声をかけるだけです。
通知が来ても、やらなくて大丈夫。忘れずにいてくれるだけで十分です。
```

**日次リマインド（ローテーション表示、3日連続で同じ文言を出さない）**
1. 今日も5分だけ、いかがですか。
2. すきま時間、見つかりましたか？
3. 5分だけ、今いる場所から。
4. 今日はどこにしましょうか。ちょっとだけ、片付けの時間です。
5. 昨日はお休みでも大丈夫。今日、また始めましょう。（直近に未実施日があった翌日に優先表示）

**初回フォロー（未起動ユーザー）**
- Day1：昨日はインストールだけで十分です。今日、1つだけやってみませんか。
- Day3：「片付けなきゃ」より先に、5分だけ試してみませんか。

**休眠再喚起（2回で打ち切り、それ以降は送らない）**
- 7日未起動：お久しぶりです。また、5分だけ始めてみませんか。
- 14日未起動：焦らなくて大丈夫。思い出した時が、はじめ時です。

**お休みチケット補充（送信は任意、アプリ内バッジのみでも可）**
```
今週分のお休みチケットが補充されました。無理せず、いつでもどうぞ。
```

- 通知は1日最大1件。日次リマインドと再喚起が重なる場合は日次リマインドを優先

### 6-5. 褒めメッセージ集
「次も頑張ろう」等、継続を促す言葉は使わない。その場の行動を肯定するだけで完結させる。

| シーン | 文言例 |
|---|---|
| タスク完了時 | ここまでで、じゅうぶんです。／少しだけ、部屋の空気が変わりましたね。／今日はここまで。それで大丈夫。／ちゃんと、5分やりました。 |
| Before/After撮影時 | 変化が、ちゃんと残りました。／この1枚が、今日の記録です。／見比べると、少し違いますね。 |
| タイマー中に途中終了 | 途中でも、やった分はちゃんと残ります。／5分やりきらなくても大丈夫。今日はここまで。 |
| 写真のみの完了扱い | 今日はこれだけでも、十分な一歩です。／手が動かない日があっても、大丈夫。 |
| ストリーク3/7/14/30/100日 | 3日、続きました。／1週間です。ちょっとずつ、積み重なっています。／2週間。日常に、少し馴染んできたかもしれません。／1か月。ここまで、よく続けてきました。／100日。数字にすると、すごい積み重ねです。 |
| お休み明け再開時 | おかえりなさい。また、ここから。／久しぶりでも、やり方は忘れていませんでしたね。 |
| 同日複数タスク | 今日はもう1つ。無理はしないでくださいね。／2つ目です。ここでやめても、じゅうぶんです。 |
| スキップ時 | 気分が乗らない日もあります。また今度で大丈夫です。／別のタスクにしますか？それとも、今日はこれで終わりでも。 |

- 表示はタスク完了直後、1〜2秒のアニメーション＋テキスト（モーダルで足止めしない）
- 「シェアする」ボタンはMVPでは設置しない

## 7. 計測要件（β検証のため必須）
以下は最低限イベントとして記録し、BIツール（Amplitude/Mixpanel等、軽量なものでよい）に送信する。

| イベント | 目的 |
|---|---|
| タスク表示 | どのカテゴリ・タスクが提示されたか |
| タスク完了 / スキップ | 着手率・完了率の算出 |
| タイマー開始 / 中断 / 完了 | 5分完遂率の把握 |
| Before/After写真の撮影有無 | 可視化機能が使われているか |
| ストリーク継続日数 | 継続率の推移 |
| 通知タップ率 | リマインドの効果測定 |

**個人情報・位置情報の取得は行わない。** 広告SDK・トラッキングSDKは導入しない（プライバシー訴求はASO上の差別化ポイントのため厳守）。

## 8. 非機能要件
- オフラインで完結する設計（タスク表示・タイマー・写真保存・ストリークはすべてローカル処理でよい。計測イベントのみオンライン送信）
- 広告非表示・トラッキングなし
- アカウント登録・ログイン不要（β版では端末内完結でよい）

## 9. 検証したい仮説（開発時に意識すること）
1. 5分×小分けタスクは、通常の「片付けよう」より着手率が上がるか
2. Before/After写真の可視化は継続動機になるか
3. どのタスクカテゴリが最も継続されるか（次期AI提案ロジックの学習データにもなる）

## 10. β版運用・KPI
- 実施規模：クローズドβ 100〜300名
- 主要指標：Day7継続率、Day30継続率、週あたり平均タスク完了数、写真投稿率
- 継続率が低い場合は、AI導入より先にタスク粒度・通知頻度などUX側の調整で改善できないかを優先的に検証する
