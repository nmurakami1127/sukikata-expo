# 実装指示書：タスクパーソナライズ／ロボット掃除機対応

対象リポジトリ：スキマかたづけ（スキかた）MVP（React Native / Flutter、1ソースiOS/Android）
参照元：`sukimakatazuke-mvp-spec.md`（公開済みMVP仕様）／要求定義書「タスクパーソナライズ／ロボット掃除機対応」（承認済み最終版）

この指示書は上記2つの企画ドキュメントを実装タスクに変換したものです。仕様の解釈に迷った場合は、企画意図（判断負荷を増やさない／選択肢を増やさない／AIを使わない）を優先し、不明点は実装せず要確認としてリストアップしてください。

---

## 0. 変更してはいけない既存挙動（regression NG）

- 「場所を選ぶ → タスクを1つ表示」の基本導線
- 5分タイマー、Before/After写真、ストリーク（お休みチケット制）、通知のロジック
- タスク完了/スキップの計測イベント
- オンボーディング5画面（新規質問を追加しない）
- AI・アカウント登録・広告SDK・外部トラッキングSDK・位置情報取得を一切導入しない

これらに触れる変更が必要になった場合は実装を止めて確認してください。

## 1. データモデル拡張

### 1-1. タスクデータスキーマ

既存タスクJSON（`id, category, title, note, cooldown_days`相当）に以下を追加。既存タスクは新フィールドなしでも動作すること（後方互換）。

```json
{
  "id": "floor_robot_001",
  "category": "床",
  "title": "床のコードを1か所だけ上げる",
  "minutes": 5,
  "tags": ["robot_vacuum", "cables", "low_decision"],
  "audiences": ["robot_owner", "robot_considering"],
  "cooldownDays": 14,
  "weight": 1
}
```

- `tags`: string[]（任意、フィルタリングには使わず分析用途）
- `audiences`: string[]。省略時は `["all"]` 扱い
- `weight`: number。省略時は `1`。表示優先度の重み付けに使用（4章参照）

### 1-2. ユーザー設定ストア（端末内ローカル）

```json
{
  "robotVacuumStatus": "owner" | "considering" | "unset",
  "robotVacuumStatusUpdatedAt": "ISO8601",
  "robotPromptDismissedAt": "ISO8601 | null",
  "robotPromptDismissedPermanently": false,
  "floorCategoryUseCountSinceLastPrompt": 0,
  "hiddenTaskIds": ["task_id", ...],
  "taskStats": {
    "<task_id>": {
      "shownCount": 0,
      "completedCount": 0,
      "skippedCount": 0,
      "lastShownAt": "ISO8601 | null"
    }
  }
}
```

`robotVacuumStatus` は3値のみ。「使用予定なし」の明示的な値は持たない（要求定義4章）。

## 2. 機能実装タスク

### 2-1. ロボット掃除機利用状況の設定

- 設定画面に「ロボット掃除機を使っていますか？」の項目を追加。選択肢：使っている／購入を検討している／未設定に戻す
- いつでも変更可能
- **オンボーディングには一切追加しない**（既存5画面フローに触らない）

**受け入れ条件**
- [ ] 未操作ユーザーの `robotVacuumStatus` は `unset`
- [ ] 設定変更で他機能（タスク表示等）が即座に反映される
- [ ] オンボーディングのXcode/画面数に変更がない

### 2-2. ホーム画面バナー（補助案内）

表示条件：
- 「床」カテゴリの利用回数が閾値に到達（閾値は実装時に定数化。例 `FLOOR_PROMPT_THRESHOLD = 3`）
- かつ `robotVacuumStatus === "unset"`
- かつ「今は設定しない」による30日抑制期間中でない
- かつ同一セッション内でバナーを閉じていない

表示禁止タイミング（既存導線への割り込み厳禁）：
- タスク表示直前 / タスク実行中 / タイマー終了時 / タスク完了直後 / 褒めメッセージ表示中

表示場所：ホーム画面上の閉じられる任意バナー（モーダルにしない）

文言：
```
ロボット掃除機を使っていますか？
使っている場合は、床のタスクを少し合わせられます。
```
選択肢：使っている ／ 購入を検討している ／ 今は設定しない

**再表示ロジック（重要・誤解しやすい箇所）**

「今は設定しない」を選択した場合：
1. `robotPromptDismissedAt` に現在日時を記録、`floorCategoryUseCountSinceLastPrompt` を0にリセット
2. 以後30日間はバナーを表示しない
3. 30日経過後も**自動では再表示しない**
4. 30日経過後に「床」カテゴリを再度利用した場合に限り、再表示候補とする
5. 「床」カテゴリの利用がなければ、30日を過ぎても表示しない
6. 再表示候補になった場合も、表示先はホーム画面バナーのみ（タスク実行前後には出さない）

→ 単純なタイマー式（30日経過で自動的に次回床タスク時に必ず出す）は要求と異なるので実装しないこと。

バナーを単に閉じた場合（設定はしていない）：同一セッション中は再表示しない。次回セッション以降の再表示は過度にならない範囲で実装（具体的頻度は要相談、暫定でセッション単位の抑制のみでよい）。

**受け入れ条件**
- [ ] 上記5タイミングでバナーが一切表示されない（自動テストでUIイベント発火順を確認）
- [ ] 「今は設定しない」後、床カテゴリを使わないユーザーには31日目以降も出ない
- [ ] 「今は設定しない」後、31日目以降に床カテゴリを使うと次回ホーム画面で再表示候補になる

### 2-3. タスク選択ロジックの拡張

現行の「場所を選ぶ→ランダム1件表示」の絞り込み順序を以下に変更：

1. 選択された場所カテゴリに属するタスク
2. `audiences` によるユーザー属性フィルタ（該当しないタスクを除外するのではなく優先度に反映。下記参照）
3. `hiddenTaskIds` に含まれるタスクを除外
4. 原則14日クールダウン期間外のタスクに絞る（3-1のフォールバック参照）
5. `weight` とタスク統計（表示回数・完了率・スキップ率）による重み付けで1件を選択

属性フィルタの扱い：
- `robotVacuumStatus === "owner"` → `audiences` に `robot_owner` を含むタスクの選択重みを上げる（除外はしない。通常タスクと共存）
- `robotVacuumStatus === "considering"` → `robot_considering` を含むタスクの重みを上げる
- `robotVacuumStatus === "unset"` → 既存MVPと同じ通常のランダム選択（属性フィルタなし）

**受け入れ条件**
- [ ] `unset` ユーザーの床タスク提示は現行MVPと出力分布が変わらない（回帰確認）
- [ ] `owner` ユーザーは `robot_owner` タスクが通常タスクより高頻度で出るが、0%になったり100%になったりはしない

### 2-4. ショートカット「ロボット掃除機前の5分」

- `robotVacuumStatus === "owner"` のユーザーにのみホーム画面に任意ショートカットとして表示
- `considering` および `unset` には表示しない
- タップ時に開くタスクプールは、通常の「床」カテゴリと**同一のタスクデータ**を参照する（専用に複製したタスクリストを持たない）。実装上は「床カテゴリ ×  `audiences` に `robot_owner` を含む」でフィルタしたビューとして実装する

**受け入れ条件**
- [ ] ショートカット用に別テーブル／別JSONファイルを作らないこと（コードレビューで確認）
- [ ] `considering`/`unset` ユーザーには一切表示されない

### 2-5. 購入検討者向け確認タスク

- `considering` ユーザーには、共通タスク（2-3のaudiences=`robot_owner`,`robot_considering`両方に属するタスク）に加え、`robot_considering` のみを対象とする確認系タスクを候補に含める
- 完了時の表現は「確認できた」系の中立的な文言のみ使用し、「使える」「対応済み」等の断定表現を含めないこと（コピーは6章参照、実装側でも文言バリデーション対象に含めることを推奨）

### 2-6. タスクカスタマイズ「今後出さない」

- スキップ操作時のメニュー、または補助メニューから「このタスクは今後出さない」を選択可能に
- 選択時、当該タスクIDを `hiddenTaskIds` に追加。以後の選択ロジック（2-3の手順3）で除外
- 通常のスキップ（1回だけ「別のタスクを見る」）は `hiddenTaskIds` に影響しない
- 設定画面に「出さない設定にしたタスク」一覧を表示し、個別に解除可能にする
- **候補不足を理由にアプリ側が自動的に `hiddenTaskIds` から削除する処理は実装しないこと**

**受け入れ条件**
- [ ] 「今後出さない」後、当該タスクは候補プール枯渇時にも再提示されない
- [ ] 通常スキップは非表示化に影響しない（別テストケースとして分離）

### 2-7. 候補枯渇時のフォールバック

原因を2種類に分けて処理する。

**A. 14日クールダウンによる不足**
非表示ではない候補が存在するが全てクールダウン期間内の場合、以下の優先順で14日未満でも再提示を許可：
1. 最終実施日が古い
2. スキップ率が低い
3. 表示回数が少ない

**B. 「今後出さない」による不足**
非表示タスクを除いた利用可能タスクが0件になった場合：
- 圧をかけないメッセージを表示：`今出せるタスクが少なくなっています。`
- 選択肢：「他の場所を見る」「出さない設定を見直す」
- `hiddenTaskIds` は自動解除しない

**受け入れ条件**
- [ ] A・Bのケースをユニットテストで分離して検証（同じ「候補0件」でも原因によって挙動が変わることを確認）
- [ ] どちらのケースでも「タスクがありません」という素のエラー表示にはならない

## 3. タスクコンテンツ

以下は企画側から提供済みのタスク文言（コンテンツ担当と実装で突き合わせ、JSONマスターに登録）。

### 3-1. 所有者・購入検討者 共通タスク（`audiences: ["robot_owner","robot_considering"]`）
床にある服を1着だけ戻す／床にあるものを3つだけ元の場所へ戻す／床のコードを1か所だけ上げる／バッグを1つだけ床から移動する／小物を3つだけ拾う／椅子の周りを1か所だけ空ける／通り道を1本だけ空ける／床に垂れている布を1か所だけ上げる／ペットのおもちゃを3つだけまとめる／床の一角だけ何もない状態にする／床にある紙類を3枚だけまとめる／スリッパを1組だけ端へ寄せる／延長コード周辺のものを3つだけ移動する／ベッド脇の床を少し空ける／ソファ前の小物を3つだけ移動する

### 3-2. 購入検討者向け追加（確認タスク、`audiences: ["robot_considering"]`）
ロボット掃除機が通りそうな場所のコードを1か所確認する／床によく置いているものを1つだけ確認する／段差やマットのある場所を1か所確認する／ロボット掃除機を置けそうな場所を1か所確認する／床まで垂れているカーテンや布を1か所確認する／よく物が集まる床の一角を1か所確認する

いずれも `minutes: 5`、`cooldownDays: 14` をデフォルトとする。**同一内容を所有者向け／検討者向けで別IDに複製しないこと。**

### 3-3. 完了時コピー
ここまでで、じゅうぶんです。／床が少し空きました。／今日はこの分だけで大丈夫です。／ひとつ分、動きやすくなりました。

購入検討者向け表現例：少しずつ、床を使いやすくできています。／使う前に気になるところを、ひとつ確認できました。

**NG表現（実装・レビュー時にチェック）**：「使える状態になりました」「準備完了です」「この部屋なら問題なく使えます」「対応済みです」等の断定表現は文言リストに含めない。

### 3-4. タスク数の目安
ロボット掃除機との関連性を持つタスク（新規＋既存共用分）を合計20件以上確保する。新規追加は上記3-1・3-2で17件あるため、既存タスクから `robot_vacuum` タグを付与できるものを数件追加すればこの目安は満たせる見込み。実装時に実数をカウントして確認すること。

## 4. 計測イベント

既存の計測基盤（Amplitude/Mixpanel等）に以下を追加。個人情報・位置情報は送信しないこと（既存方針の継続）。

| イベント名 | 発火タイミング |
|---|---|
| `robot_status_set` | ロボット掃除機利用状況を設定/変更したとき |
| `robot_prompt_shown` | ホーム画面バナーを表示したとき |
| `robot_prompt_dismissed` | バナーを閉じた/「今は設定しない」を選んだとき |
| `robot_task_shown` | ロボット掃除機関連タスク（owner/considering向け）を表示したとき |
| `robot_task_completed` | 同上タスクを完了したとき |
| `robot_task_skipped` | 同上タスクをスキップしたとき |
| `task_hidden` | 「今後出さない」を選択したとき |
| `task_unhidden` | 非表示設定を解除したとき |
| `robot_shortcut_opened` | 「ロボット掃除機前の5分」ショートカットを開いたとき |
| `task_pool_fallback` | 候補枯渇フォールバックが発動したとき（A/Bどちらの原因かをプロパティに含める） |

## 5. スコープ外（今回は実装しない）

以下は明示的に対象外です。関連コードや依存関係を追加しないこと。

- ロボット掃除機の商品紹介／購入リンク／アフィリエイト／成果報酬計測
- メーカー広告・メーカーアカウント連携
- ロボット掃除機の直接操作・状態取得・部屋マップ取得
- AI画像解析
- 一般ユーザー向け「目的を選ぶ」モード（場所選択に加える必須ステップの追加）
- 詳細な生活環境アンケート
- 課金機能

## 6. 実装順序の提案

1. データモデル拡張（1章）＋既存タスクJSONの後方互換確認
2. タスク選択ロジックの拡張（2-3）＋回帰テスト（`unset`ユーザーの挙動が変わらないこと）
3. ロボット掃除機利用状況の設定画面（2-1）
4. タスクコンテンツ投入（3章）とタグ付け
5. 「今後出さない」＋非表示管理（2-6）
6. フォールバックロジック（2-7）
7. ホーム画面バナーと再表示ロジック（2-2）※最も条件分岐が複雑なので個別にユニットテストを厚くする
8. ショートカット「ロボット掃除機前の5分」（2-4）
9. 計測イベント実装（4章）
10. 結合テスト・回帰テスト一式

## 7. 要確認事項（実装前にPMへ確認）

- 2-2「床カテゴリ利用回数」の閾値（暫定 `FLOOR_PROMPT_THRESHOLD = 3` としているが要確定）
- バナーを単に閉じた場合の再表示頻度（「同一セッション中は再表示しない」以上の具体的な間隔は要求定義に明記なし）
- 3-4のタスク総数が実際に20件を満たすかは、既存タスクJSONの棚卸し後に確定

これらは実装をブロックする項目ではないため、暫定値で進めつつPM確認後に調整可能な形（定数化）で実装すること。
